### 3.2 ★ 등록층 실측 — 손편집이 통째로 사라진다

- **양쪽 다 매니페스트를 런타임에 읽는다.** `~/.claude.json`의 `mcpServers`가 비었는데 플러그인
  MCP 도구가 살아 있고, Codex의 `[mcp_servers.*]`에는 우리 손편집분만 있는데 `codex mcp list`는
  플러그인 선언 서버까지 낸다. 호스트가 남기는 자국은 각각 **한 줄**이다.
- **프로브 플러그인으로 우리 산출물을 직접 검증했다** — Claude는 `--plugin-dir`로 도구가 실제로
  뜨고, Codex는 `plugin marketplace add` → `plugin add` → `mcp list`가 공유 `.mcp.json`의 서버를
  전부 `enabled`로 낸다.
- **`command` 형태 중 bare PATH 이름만 양쪽에서 산다.** `${PLUGIN_ROOT}`는 Claude에서 마운트
  실패. 우리는 이미 bare 이름이므로 **등록물 내용은 안 바뀐다.**
- **`codex plugin add`는 `codex mcp add`의 파괴적 직렬화기를 타지 않는다** — 458바이트 씨앗
  파일 전후에 바뀌거나 사라진 줄이 **0**(헤더 위 주석·`args = []`·인라인 `env` 전부 생존).
- **`[features] hooks`는 새 홈에서 기본 켜짐** — 사용자가 설정 파일에 한 줄도 칠 필요가 없다.
- **한 벌이 양쪽을 섬긴다**: `.claude-plugin/marketplace.json` · `.mcp.json` · `hooks/hooks.json` ·
  `skills/`. 중복은 `plugin.json` 둘뿐이고, 그 이유 중 하나가 **훅 키의 비대칭**이다
  (Claude는 관례로 이미 로드하므로 또 적으면 `Duplicate hooks file detected`).

### 3.3 ★ 가시성·채택층 실측 — 전제가 두 번 뒤집혔다

- **MCP 스키마는 프롬프트에 안 들어간다**(Tool Search). 서버 셋 + 스킬 + 훅을 붙여 **+399토큰**.
- **그러나 지연된 도구는 쓰이지 않는다** — 참조 구현 62일 코퍼스에서 한 도구가 **호출 0회**
  (*"never unwanted, only unmentioned"*). 전부-상시도 전부-지연도 틀렸다.
- **`alwaysLoad: true`는 +3,235토큰 + 프롬프트 캐시 파괴.** 서버 단위 플래그는 토큰만 무는 게
  아니라 **호스트의 지연 로드 기능을 사용자에게서 빼앗는다**(소유자 판정 → D99 근거 ②).
- **`outputSchema`는 프롬프트에 안 실린다.** 그 키만 다른 서버 두 벌로 32,172자를 더해도
  **38,273 대 38,273**. 콜드 통제군에서도 +12토큰(이름 접두 몫). → **줄일 대상은
  `description`·`inputSchema`뿐이고 `outputSchema` 제거는 무의미하다.**
- **설득은 실패한다** — 참조 구현이 최대치 프롬프팅으로 유기적 채택률 **3.82%**를 쟀고,
  `MANDATORY`·`BLOCKED`·`Do NOT`·이모지는 38시행 A/B로 **역효과**가 측정돼 금지 토큰표에 올랐다.
  실제로 값을 낸 것은 서브에이전트 프롬프트 강제 주입(사용량의 80%)·수동 색인·진입 도구 상시화.

### 3.4 ★ 훅 실측 — 우리 현행 코드에 직접 걸리는 셋

- **발화한다, 양쪽 다.** Claude는 프로브 훅으로 직접(마커 + 거부), Codex는 **설정 무변경으로**
  증명했다 — 설치된 플러그인의 훅이 `process.env.PLUGIN_DATA`에 상태를 쓰고 그 코드가
  **`PLUGIN_DATA`의 존재 자체로 Codex를 판별**하는데, 그 파일이 Codex 플러그인 데이터
  디렉터리에 실재한다. 다른 프로세스는 쓸 수 없다.
- **Codex의 플러그인 환경 변수 둘**: `PLUGIN_ROOT`(경로 치환) · `PLUGIN_DATA`(전용 쓰기 디렉터리).
- **거부 규칙**: 종료 코드 **2**(스트림 무관) 또는 종료 코드 0 + stdout의 `permissionDecision:
  "deny"` JSON. **종료 코드 1·3은 거부가 아니다** → `PreToolUse`는 보안 게이트가 될 수 없다.
- **Windows에서 훅 `command` 문자열은 Git Bash가 실행한다**(`$0=/usr/bin/bash`, 5.3.15). MSYS
  인자 변환이 Windows 셸 문법을 **조용히** 망가뜨린다 → **`command`+`args` 배열 형태를 쓴다.**
  현행 `buildHookCommand`는 문자열이고 `hookCmd`에 `args` 필드가 없다 — 이관 시 바꾼다.

## 3.8 ★ 게시 종단 검증 — 공개 원격에서 양쪽 설치 성공

산출물을 `main`에 올리고 **공개 원격에서** 두 호스트에 설치했다.

| 호스트 | 결과 |
|---|---|
| Claude | `plugin marketplace add <owner>/<repo>` → `plugin install` → `plugin:context-router:ctr … ✔ Connected` |
| Codex | 같은 형태 → `ctr … enabled`, 버전 `0.19.0` |

같은 저장소·같은 공유 `plugin/mcp.json`·같은 스킬. 사용자의 진짜 설정은 격리했다 — Claude는
임시 `CLAUDE_CONFIG_DIR`, Codex는 임시 `CODEX_HOME`.

**그 과정이 낳은 관측 넷** (설계서 A⑧·A⑨·§5-11·D98):

1. **★ 같은 명령줄의 서버는 조용히 버려진다.** 처음 마운트 실패의 원인이었다 — 저장소 안
   `ctr-exec`가 `--enable ingest,net`으로 완전히 같았다. **모든 마이그레이션 사용자가 만난다.**
2. Codex는 두 마켓플레이스 파일이 함께 있으면 **`.agents/plugins/marketplace.json`**을 읽는다.
3. 설치는 **저장소를 통째로 클론**한다 — 긴 경로에서 `Filename too long`으로 죽는다.
4. Claude가 `mcpServers`를 **경로 문자열로도 받는다** — 루트 `.mcp.json` 자리를 안 쓰고도 한
   파일이 양쪽을 섬긴다. `.gitignore`를 건드릴 필요가 없어졌다.
