> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to
> implement this plan task-by-task.

**Goal:** 등록·가드·지침을 플러그인 매니페스트로 옮기고 **호스트 설정 파일에 쓰는 코드를 전부
없앤다.** 그리고 남는 도구 표면을 도구 단위 가시성으로 다시 세운다.

**스펙:** `docs/context-router-design-v0.19-ko.md` (D96–D101). **계약과 이 계획이 어긋나면
스펙이 이긴다** — 어긋남을 발견하면 멈추고 보고하라.

테스트는 `go test -p 1 -count=1`.

## 이 계획 밖에서 이미 닫힌 것 (컨트롤러가 직접 측정, 2026-08-07)

D97의 **배송 조건 셋**은 태스크가 아니라 전제다. 셋 다 이 계획 시작 전에 닫혔다.

1. **훅 파일을 매니페스트에 싣는다**(§5-8) — `hooks/hooks.json`(Claude, 관례 경로, 선언 없음) ·
   `hooks/codex-hooks.json`(`.codex-plugin/plugin.json`이 `"hooks"` 키로 선언). 두 파일인 이유:
   러닝 서브커맨드가 호스트마다 다르고(`hook` 대 `codex-hook`) 이벤트 집합도 다르다.
   `[실측]` 이 머신에 설치된 Codex 플러그인 둘이 정확히 같은 두 파일 구조다.
2. **왕복 바이트 비교**(§5-10) — `[실측]` Codex: `marketplace add`→`plugin add`→`remove`→`add`→
   `remove`→`marketplace remove` 완전 왕복이 씨앗 파일과 **바이트 동일**(sha `C02D634F…`, 277B).
   주석·미지 키·미지 테이블·헤더 바로 위 주석·`args = []`·인라인 `env` 전부 생존. 각 단계는
   순수 추가/순수 제거다. Claude: 사용자 데이터는 전부 살지만 `settings.json`이 **통째로
   재직렬화**되고(들여쓰기·키 순서) uninstall이 `"enabledPlugins": {}`를 남긴다. 주석이 든
   `settings.json`은 `Invalid JSON syntax`로 **exit 1 + 파일 무변경**(fail-closed).
3. **`doctor` 감지원**(§5-13) — 판정: **`codex mcp get`도 `--json`도 부르지 않는다.** 무효 TOML
   코호트에서 실패하고 `--json`은 `env`를 평문으로 낸다. 대신 **읽기 전용 줄 위치 탐지기**를
   최소 크기로 새로 둔다(Task 3). D97 계약 2의 "어느 줄인지 짚는다"가 그렇게 살아남는다.

**훅 발화 실측** `[실측]`: Claude에서 `--plugin-dir`로 올린 이 저장소의 매니페스트가
`SessionStart`·`PreToolUse`·`PostToolUse`를 전부 발화시켰다(`cc:` 접두 세션 + `Glob`·`Read`의
tool_call 이벤트 8건, drops 0). **`command` + `args` 배열 형태 · `commandWindows` 없이 · Windows
에서** 성립한다. Codex 쪽 형태 판정은 컨트롤러가 별도로 닫는다.

## Global Constraints

- **호스트 설정 파일에 쓰지 않는다**(D96 계약 1). 이 브랜치가 끝나면 우리 코드는
  `~/.claude.json`·`.claude/settings.json`·`~/.codex/config.toml`·`.mcp.json` 중 **어느 것에도
  쓰지 않는다.** 살아남는 쓰기는 하나뿐이다: `hook uninstall`의 훅 그룹 **제거** 한 방향.
- **훈계 어휘 금지**(D100 계약 2). 도구 설명·훅 사유·`doctor` 문면·`hostSnippet`·README에
  `MANDATORY` · `BLOCKED` · `Do NOT` · `Never` · `PREFER X OVER Y` · ✅/❌ · 이모지를 쓰지 않는다.
  **부정으로 해명하지 않는다** — 리다이렉트는 대체 목적지만 말한다.
- **`outputSchema`를 건드리지 않는다**(D99 계약 4). 프롬프트 비용 0이 실측됐다. 줄일 대상은
  `description`과 `inputSchema`뿐이다.
- **새 의존 금지.** 표준 라이브러리와 이미 있는 모듈만 쓴다.
- **파일 출력**: UTF-8(BOM 없음), LF.
- **게이트 다섯을 매 태스크 끝에서 하나도 빼지 않고 돌린다**:
  `go build ./...` · `go vet ./...` · `go test -p 1 -count=1 ./...` · `gofumpt -l .`(무출력) ·
  `golangci-lint run --max-same-issues=0 --max-issues-per-linter=0 ./...`(`0 issues`).
  session-48이 이 중 둘을 빠뜨려 릴리스 차단 둘을 맞았다.
- **베이스라인**(이 브랜치 시작 시점 실측): `go build` 0 · `go vet` 0 · `gofumpt` 무출력 ·
  `golangci-lint` `0 issues` · 테스트는 **`internal/exec`만 실패**하고 전부 이 호스트의
  PowerShell 실행 정책이다(`running scripts is disabled on this system`). **회귀가 아니다.**
  판정 규칙 하나: 실패 패키지가 이번 변경이 만진 패키지인가.
- **테스트 실행 시간**: `./internal/cli`는 약 50초, 전체는 약 3분이다. 태스크 중에는 `-run`으로
  좁혀 돌리고 태스크 끝에 한 번 전체를 돌린다. `-p 1`은 생략하지 않는다.
- **파일 통째 재작성 금지.** 긴 테스트 데이터는 `strings.Repeat` 또는 testdata로 만든다.
- **테스트 안 비밀 문자열**은 런타임 분할 리터럴(`"xox"+"b-..."`)로 쓴다 — 푸시 보호 오탐 방지.
- **커밋 트레일러**: `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`
- **증거 등급**을 보고 문장마다 붙인다: `[실측]`(이 머신에서 돌려 확인) · `[문서]` · `[추정]` ·
  `[미실측]`. 돌려 보지 않은 것을 돌려 본 것처럼 적지 않는다.

### Task 1: D99 — 진입 도구 둘만 상시 로드, 나머지 여섯은 설명 꼬리에 색인

**왜:** `[실측]` MCP 도구 스키마는 프롬프트에 지연 적재되어 서버 셋을 붙여도 +399토큰이지만,
서버 단위 `alwaysLoad: true`는 +3,235토큰에 프롬프트 캐시를 깨뜨린다. 그런데 `[참조실측]`
지연된 도구는 62일 코퍼스에서 **호출 0회**였다. 전부-상시도 전부-지연도 틀렸다. 그리고 서버
단위 플래그는 비용 문제가 아니라 **호스트의 지연 로드 기능을 사용자에게서 빼앗는 기능 회귀**다.

**Files:**
- Modify: `internal/mcp/mcp.go`
- Test: `internal/mcp/mcp_test.go`

**Requirements:**

1. `ctr_search`와 `ctr_index`의 `mcp.Tool` 리터럴에 `Meta: mcp.Meta{"anthropic/alwaysLoad": true}`
   를 단다. **다른 어떤 도구에도 달지 않는다.** `[실측: go doc]` 설치된 SDK의 `mcp.Tool`은
   `Meta \`json:"_meta,omitempty"\`` 를 임베드하고 `mcp.Meta`는 `map[string]any`다.
2. 두 진입 도구의 `Description` **꼬리에** 지연 도구 여섯의 **이름 + 한 줄 용도**를 붙인다.
   호출 방법·인자·예시는 적지 않는다(D99 계약 2). 지연 여섯:
   `ctr_fetch` · `ctr_transform` · `ctr_record_event` · `ctr_session_summary` ·
   `ctr_export_events` · `ctr_fetch_and_index`.
3. 그 색인 문면은 **패키지 상수 하나**로 두고 두 도구가 같은 상수를 참조한다 — 문면이 두 벌로
   갈라지면 하나만 갱신되는 것이 이 저장소의 D13 반파편화가 막는 형태다.
4. `Meta`를 다는 자리 위 주석에 **Claude 한정 최적화**임을 적는다: `"anthropic/alwaysLoad"`는
   Anthropic 벤더 확장이고 `[문서]`, `[실측]` Codex는 미지 매니페스트 필드를 조용히 버린다 —
   Codex 등가 기제는 **재지 않았다**(§5-4).
5. `inputSchema` · `outputSchema` · `Annotations` · 핸들러 본문은 **건드리지 않는다.**
6. 어휘 규칙(Global Constraints)을 지킨다.
7. `ctr_execute` · `ctr_execute_file` · `ctr_global_search`는 대상이 아니다 — 각각 exec 프로필
   opt-in과 별도 서버다.

**Tests (`internal/mcp/mcp_test.go`에 추가):**

- `NewServer`를 `Enable: []string{"ingest","net"}` + `Session` 있음으로 띄우고 `ListTools`의
  결과에서 `_meta`의 `anthropic/alwaysLoad`가 참인 도구 이름 집합이 **정확히
  `{ctr_search, ctr_index}`** 임을 단정한다. 기존 테스트의 `ListTools` 사용례를 그대로 따른다.
- 두 진입 도구의 `Description`이 지연 여섯의 이름을 **전부** 담는지 단정한다(여섯 개 이름을
  루프로 확인 — 하나라도 빠지면 실패).
- 어느 도구 설명에도 금지 어휘(`MANDATORY`, `BLOCKED`, `Do NOT`, `Never`, `PREFER`)가 없음을
  단정한다.
- **기존 `TestSchemaTokenBudget`(mcp_test.go:251 부근)이 이 변경으로 움직인다.** 그 테스트를
  읽고, 예산을 새 실측값으로 재기준선하되 **왜 늘었는지 주석에 남긴다.** 예산 자체를 없애거나
  단정을 약화시키지 않는다.

**Verification (게이트 다섯 전부):** 위 Global Constraints의 다섯 명령.

### Task 2: D101 — `CTR_ENABLE` 환경 변수와 배송 버전 `0.19.0`

**왜:** 플러그인 경로에서는 `plugin/mcp.json`의 `--enable ingest,net`이 매니페스트에 고정이라,
`CTR_ENABLE`이 없으면 Codex 사용자가 프로필을 바꿀 수단이 사라진다(지금은
`hook install --enable-exec`이 그 자리였고 Task 5가 그것을 지운다). D101 계약 1·2가 그 답이다:
서버는 환경 변수만 읽고, 프로필 목록은 **쉼표 구분 문자열 하나**이며, 없으면 현행 기본이다.

**Files:**
- Modify: `cmd/context-router/main.go` (`parseServerFlags`, main.go:43-76 부근)
- Modify: `internal/buildinfo/buildinfo.go`
- Test: `cmd/context-router/main_test.go`

**Requirements:**

1. `--enable`이 **빈 문자열일 때만** `CTR_ENABLE`을 읽는다. 플래그가 주어지면 플래그가 이긴다
   (빈 값으로 명시한 `--enable=`도 환경 변수를 읽는다 — 구분할 수단이 없고, 그 구분에 값이 없다).
2. 값의 문법은 `--enable`과 **같다**: 쉼표 구분, 항목별 공백 트림, 빈 항목 무시.
3. **모르는 이름은 오류다** — 조용히 떨어뜨리면 사용자가 프로필이 켜졌다고 오인한다. 오류
   문면에 **입력 원문을 담지 않는다**(규약 §6 — 사용자 입력 에코 금지). 허용 이름은 기존
   `--enable`이 받는 것과 같은 집합이다. 기존에 `--enable`의 미지 이름 검증이 이 경로에 없다면
   **없는 채로 두고**(범위 밖) 환경 변수 값도 같은 규칙을 따른다 — 즉 두 입구의 규칙이 갈리지
   않는 쪽을 택하고, 어느 쪽을 택했는지 보고에 적는다.
4. 환경 변수 읽기는 **테스트에서 주입 가능해야 한다**. 이 패키지의 기존 관례를 먼저 보고
   (`getenv func(string) string` 파라미터 방식이 `internal/cli`·`internal/hook`의 관례다) 그것을
   따른다. `t.Setenv`로 충분하면 그것도 좋다 — **새 전역 변수를 만들지 않는 쪽**을 택한다.
5. `internal/buildinfo/buildinfo.go`의 `productVersion`을 `"0.18.0"` → `"0.19.0"`으로 올린다.

**Tests:**

- `CTR_ENABLE=ingest,net`이 `--enable` 부재 시 `f.Enable`을 채우는지.
- `--enable exec`가 주어지면 `CTR_ENABLE=ingest`를 **무시**하는지.
- `CTR_ENABLE`이 없거나 빈 문자열이면 현행 기본 동작 그대로인지.
- 공백이 낀 값(`" ingest , net "`)이 정규화되는지.
- 버전 상수를 문자열로 단정하는 기존 테스트가 있으면 함께 갱신한다.

**Verification (게이트 다섯 전부).**

### Task 3: `doctor`의 최소 감지원 — 읽기 전용 줄 위치 탐지기

**왜:** D97 계약 2는 `doctor`가 **옛 방식 손편집 등록물을 감지해서 알리고 어느 줄인지 짚는
것**을 남긴다. 그 능력이 지금은 `codex_toml.go`(1,989줄)에 들어 있고 Task 5가 그것을 지운다.
`[실측]` 대체 후보였던 `codex mcp get`은 **무효 TOML에서 실패하고** `--json`은 `env` 값을
평문으로 낸다 — 도움이 가장 필요한 코호트에서 실패하고 자격증명을 유출한다. **그러므로
`doctor`는 그 명령을 부르지 않는다.** 대신 최소 크기의 자체 탐지기를 둔다.

**Files:**
- Create: `internal/cli/codex_scan.go`
- Create: `internal/cli/codex_scan_test.go`

**Requirements:**

1. 순수 함수 하나를 만든다 — 파일 IO·시간·난수 없음(읽기 전용 `doctor`가 부르는 경로다).
   시그니처 예: `func codexServerHeaders(b []byte) []codexHeaderHit`,
   `type codexHeaderHit struct { Name string; Line int }`. `Line`은 **1-기반**이다.
2. 줄 단위로 훑어 `[mcp_servers.<이름>]` 형태의 **테이블 헤더 줄만** 잡는다. 앞뒤 공백과
   헤더 안 공백을 허용한다. 이름은 헤더에서 그대로 떼어 낸다(따옴표가 있으면 벗긴다).
3. **TOML 파서를 쓰지 않는다.** 이것은 판정이 아니라 **보고**이고, 무효 TOML에서도 동작하는
   것이 존재 이유다.
4. **알려진 한계를 함수 주석에 적는다**: 다중행 문자열 안의 줄이 헤더처럼 보이면 오탐한다.
   보고 전용이라 오탐의 비용이 "있지도 않은 줄 번호를 알린다"뿐이고, 그것을 없애는 값이
   파서 전체다 — 그 교환을 D97이 이미 판정했다.
5. 선두 UTF-8 BOM을 판정 전에 뗀다(기존 `trimBOM`이 이 패키지에 있다 — 재구현하지 않는다).
6. **이 태스크는 `doctor`를 아직 배선하지 않는다.** 함수와 테스트만 만든다 — 배선은 Task 4다.
   `codex_toml.go`도 아직 지우지 않는다.
7. **새 파일은 이 둘뿐이다.** 기존 파일을 수정하지 않는다(임포트 추가 포함).

**Tests:**

- 헤더 하나·여럿·없음.
- 들여쓰기·헤더 안 공백(`[ mcp_servers . foo ]`)·따옴표 있는 이름.
- **무효 TOML에서도 헤더를 찾는다**(예: 닫히지 않은 배열이 뒤에 있는 파일) — 이것이 존재 이유다.
